# Керівництво адміністратора

## 1. Перший запуск (15 хвилин)

1. `olian setup`: створить `.env` зі свіжими секретами. **Збережіть копію** `OLIAN_BACKUP_KEY` і `OLIAN_PII_SALT` у менеджері паролів.
2. `olian project create <id> --name "<назва>" --goal "<мета>" --sandbox local`.
3. У BotFather створіть **окремого** бота для моніторингу; вимкніть Privacy Mode (`/setprivacy` → Disable) або зробіть його адміністратором.
4. `olian monitor init <id> --bot-token <токен> --topics 'тема1*,тема2*' --category <назва> --profile "<хто ваш клієнт>"`.
5. Додайте бота в погоджені групи/канали (за згодою власників).
6. `olian token <id> --label operator --role manager`, `olian serve`, відкрийте `/admin`, вставте токен.
7. **Джерела** → «Чати, де є бот» → «Погодити». З цього моменту повідомлення збираються.

## 2. Правила: як писати

* **Фрази** (будь-яка): теми й товари. `вілл*` це префікс (віллу, вілли, віллі).
* **Ознаки наміру** (достатньо однієї): «шукаю, потрібен, підкажіть, купити, замовити, ціна». Саме це відсікає «просто згадку теми».
* **Обов'язкові** (усі): коли потрібні одночасно кілька термінів (місто + послуга).
* **Виключення**: «продам, пропоную, for sale, промокод».
* Пишіть формами всіма мовами ваших груп (uk/ru/en/cs): стартові набори є в `olian/presets.py`.
* Після змін натисніть **«Тест на збережених»**, потім перевірте на вибірці: `olian monitor evaluate <id> samples.json`.
  Метрики: precision (скільки відібраного справді лід), recall (скільки ліда не пропущено), `level1_missed_relevant`
  (скільки ліда відсікли самі правила, тобто чого не вистачає у фразах).

## 3. Робота оператора з лідами

* **Новий** — впевнена класифікація; **На перевірці** — сумнівно або модель була недоступна (див. причину).
* Відкрийте лід: текст, посилання на оригінал, **чому відібрано**, повторні збіги, історія. Рішення:
  **Релевантний / Нерелевантний** (це навчальний сигнал і метрика якості), **Опрацьований** (після ручної взаємодії, запишіть результат),
  **Виключений** (не показувати).
* Нотатки й результат ручної обробки зберігаються в картці й журналі.

## 4. Особисті повідомлення лідам

### 4.1. Що потрібно для кожного акаунта: і чого НЕ потрібно
| Потрібно | Не потрібно |
|---|---|
| **Номер телефону**, який отримає код входу **один раз** (SMS або Telegram на іншому пристрої) | Старий смартфон на кожен акаунт |
| `api_id` і `api_hash` з my.telegram.org (для цього акаунта) | Постійно ввімкнений телефон, браузер, Telegram Web |
| Двоетапна перевірка (2FA) на акаунті: рекомендовано | Проксі, VPN, емулятори |
| Окремий акаунт для роботи, **не основний особистий** | Купувати «готові» сесії (це чужі акаунти) |

Після входу сервер зберігає сесію **зашифрованою** (`OLIAN_SESSION_KEY`) і далі працює без телефону. Номер потрібен лише
щоб отримати код, і ще раз, якщо сесію відкликали.

### 4.2. Підключення
Панель → **Акаунти** → «Підключити акаунт» (назва, номер `+380…`, api_id, api_hash) → «Надіслати код» → введіть код (і пароль 2FA,
якщо є). Або в терміналі: `olian tg login <проєкт> acc1 --phone +380XXXXXXXXX --api-id 123456` (код і api_hash вводяться
прихованим вводом). Створюється відправник `acc1` з **низьким лімітом**. Перелік: `olian tg list <проєкт>`.

### 4.3. Увімкнення «писати авторам»
За замовчуванням лідам з моніторингу писати **не можна**. Адмін вмикає це свідомо: панель → Акаунти → «Холодний контакт» → «Дозволено»
(або `outreach.cold_contact`). Рішення пишеться в журнал. Для адресації потрібен `@username` автора:
`monitor.store_username: true` (для id без username ще `author: raw`). Потім:
* вручну: у картці ліда **«Почати діалог»**: агент пише перше повідомлення, ви його схвалюєте (за замовчуванням), система відправляє у межах лімітів;
* автоматично: `monitor.autopilot: {"enabled": true, "min_confidence": 0.7, "brief": "що пропонуємо"}`; щоб відправляти **без схвалення**,
  `outreach.require_approval: false`. Рекомендація: перші дні лишайте схвалення людиною й читайте чернетки.

### 4.4. Як агент веде діалог
Перше повідомлення пишеться під конкретний допис людини, коротко, з одним запитанням. На відповіді агент реагує сам (відповідь
ідеально на запитання, далі діалог), класифікує: **цікаво** → створює завдання вам із готовою відповіддю; **не цікаво** → лід закривається; **стоп** →
стоп-лист назавжди. Після `max_conversation` (8) повідомлень агент зупиняється й передає людині. Агент не вдає з себе конкретну людину й чесно
відповідає, якщо його спитають, чи він бот. Спілкується українською, якщо людина пише українською.
Для найкращої безпеки задайте `llm` (прямий виклик моделі без інструментів); інакше текст сторонніх іде в агента Hermes без інструментів Olian,
але з його власними вбудованими.

### 4.5. Захист: що відбувається автоматично
Ліміти на акаунт із розгоном (3→5→8→ваш ліміт на день), 3 повідомлення на людину без відповіді й пауза 72 год, загальний ліміт проєкту,
вікно годин (за замовчуванням 9–20 UTC; для України `window.utc_offset: 3`), стоп-лист, футер із відпискою в першому повідомленні,
**вимикач**: `FloodWait` ставить акаунт на паузу рівно на вказаний час; `PEER_FLOOD` (Telegram обмежив акаунт), втрата сесії, скарги чи
багато відписок зупиняють відправлення, а вмикає лише адмін. Людина завжди лишається за **одним** акаунтом: якщо він зупинений,
її повідомлення чекають, а не передаються іншому.

> **Чесно.** Жодна з цих мір не гарантує, що Telegram не обмежить акаунт: масові повідомлення незнайомцям це саме те, що його
> антиспам відстежує, а скарги отримувачів вирішальні. Тримайте обсяги малими, пишіть лише тим, кому це справді релевантно, і
> розглядайте акаунти як витратний ресурс. Ми **не** маскуємо автоматизацію й не обходимо обмеження.

## 5. Запити суб'єктів даних і строки

* Видалення за запитом: `monitor.erase_author` (за Telegram ID) або «Видалити лід». Дія пишеться в журнал без ID.
* Строки: повідомлення 14 днів, ліди 180 днів (`monitor.retention_days`, `lead_retention_days`), очищення щогодини.
* Автор за замовчуванням псевдонімізований (HMAC із сіллю на проєкт). `author: raw` лише за правової підстави.
* До запуску: оцінка впливу (DPIA), політика конфіденційності, інформування за ст. 14 GDPR, перевірка правил груп і умов Telegram.

## 6. Інциденти

| Подія | Дії |
|---|---|
| Токен бота витік | BotFather → `/revoke`; `olian project config` з новим токеном (збір відновиться сам) |
| Токен проєкту/адмін-ключ витік | `olian token-revoke <id> <label>` миттєво скасовує токен (список: `olian tokens <id>`); ротація: `olian token <id> --label X --replace`; змініть `OLIAN_API_KEY` і перезапустіть |
| Файл сесії (канал B) витік | Telegram → Settings → Devices → завершити сесію; створити нову, старий файл видалити |
| Відправник `tripped` | `outreach.senders` → причина; усунути; `outreach.reset_sender` (admin) |
| Джерело `unavailable` | чат закрив доступ або бота видалили: домовтесь із власником групи, потім «Увімкнути» |
| Скарга/вимога суб'єкта | `outreach.stop` + `monitor.erase_author` |
